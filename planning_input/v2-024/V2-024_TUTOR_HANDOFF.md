## Tutor behavior

- Shared strict packet reuses `AssessmentResult`, criterion and event evidence contracts. It includes six domain scores, critical outcomes, applied score caps/penalties, authored windows, committed action/time evidence, authored case competencies and separate approved evidence collections.
- The existing Secure AI Gateway / OpenAI Responses provider is reused. Tutor baseline is `gpt-5.6-terra`, `low`, 1000 output tokens, 22-second timeout, one attempt; model policy `model-policy.tutor.terra-v1`, prompt/output version 1.0. No other capability's selected policy changes. Existing provider keeps `store:false` and no tools.
- Expo generation is intentionally **reference-only AI prioritization** plus bilingual deterministic templates, not unconstrained clinical prose. AI may select up to five existing missed/triggered criteria and approved excerpt IDs. All facts, scores, timing, titles and citation metadata are rendered from server evidence, never generated by AI. Unsupported references, duplicates, completed/pending criteria as learning failures, invented narrative, score fields or citation metadata are rejected.
- This choice makes grounding enforceable, rather than claiming that a free-text validator can prove medical accuracy. Rich paraphrase/medical explanation is not claimed. Authored rubric significance, applied critical effects and exact evidence remain visible.
- Native sections are added to the existing Assessment panel. No full UI redesign. Review-only button is labeled "Review debrief snapshot"; published ended sessions show "Generate Tutor debrief".
- Bounded in-memory memoization uses principal, Session, locale, packet hash and prompt version. Identical requests reuse results; different-language reuse of a known key is rejected. At most two AI generations per Session/language in the current server instance; at capacity the deterministic template remains available. Cross-restart durable Tutor storage is not implemented. Trusted gateway capacity remains required for live composition.
